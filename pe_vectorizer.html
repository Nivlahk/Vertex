PE loop vectorizer

Drop in a real Windows .exe. This parses the actual PE structure, scans .text for one specific, recognizable loop shape, and — only if it's really there — patches in a real AVX2 replacement and hands you back a downloadable file. Nothing here executes anything; you run and time both files yourself.
Honest scope: two real pattern families, each independently proven safe and verified via real execution. (1) index × C stores, C a power of 2 from 2–16. (2) out[i] = in1[i] OP in2[i] for OP ∈ {+, −, ×}, gated by a real runtime aliasing check — since the pointers are function parameters with no statically-knowable bounds, the tool checks whether they actually overlap at the moment of each real call and only vectorizes when they don't, falling back to the always-correct scalar path otherwise (verified against the specific dangerous case: a shifted, partial overlap that would silently corrupt data if vectorized naively — correctly caught and handled). Recognition for both happens by decoding real x86 and translating through the real SEER representation, so it's invariant to which specific instruction encoding a compiler chose. Neither family is a general optimizer: constants that aren't powers of 2 use a structurally different, unrecognized loop shape; other operations, other loop shapes, and struct-field (not bare-array) stores are real, named, unbuilt future work, not silently guessed at. Most binaries won't match either family, and you'll get a clear "no match" rather than a guess.
